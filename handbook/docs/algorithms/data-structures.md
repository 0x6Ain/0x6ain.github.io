# 자료구조와 시간복잡도

## Time Complexity 관점에서 본 기본 자료구조

| 자료구조 | 탐색 | 삽입 | 삭제 | 특징 |
|---|---|---|---|---|
| Array | O(1) (인덱스) / O(n) (값) | O(n) | O(n) | 메모리에 연속 배치, 인덱스 접근이 빠름 |
| Linked List | O(n) | O(1) (위치를 알 때) | O(1) (위치를 알 때) | 삽입/삭제가 빠르지만 임의 접근이 느림 |
| Stack | - | O(1) | O(1) | LIFO. 함수 호출 스택, 실행 취소(undo) |
| Queue | - | O(1) | O(1) | FIFO. 작업 대기열, BFS |
| HashMap | O(1) 평균 | O(1) 평균 | O(1) 평균 | 키-값 저장, 해시 충돌 시 성능 저하 |
| Tree | O(log n) (균형 트리) | O(log n) | O(log n) | 계층 구조, 정렬 유지(BST) |
| Heap | O(1) (최댓값/최솟값 조회) | O(log n) | O(log n) | 우선순위 큐 구현에 사용 |
| Graph | 구현에 따라 다름 | - | - | 노드와 간선으로 관계 표현 |

## HashMap이 왜 O(1)인가?

HashMap은 키를 **해시 함수**에 넣어 나온 값을 배열의 인덱스로 사용해
데이터를 저장한다. 배열의 인덱스 접근은 O(1)이므로, 해시 함수 계산이
O(1)이라면 저장/조회도 평균적으로 O(1)이 된다.

"평균"이라고 하는 이유는, 서로 다른 키가 같은 인덱스로 매핑되는
**충돌(Collision)**이 발생할 수 있고, 충돌이 많아지면 실제로는
O(n)에 가까워질 수 있기 때문이다.

## 충돌은 어떻게 해결하는가?

- **Chaining(체이닝)** — 같은 인덱스에 여러 키가 매핑되면 그 자리에
  Linked List(또는 Tree)로 연결해 모두 저장한다. Java의 HashMap이
  이 방식을 사용하며, 한 버킷에 항목이 많아지면(자바 8+ 기준 임계치
  초과 시) Tree로 전환해 최악의 경우도 O(log n)으로 개선한다.
- **Open Addressing(개방 주소법)** — 충돌이 나면 다른 빈 슬롯을
  찾아 저장한다(선형 탐사, 이차 탐사, 이중 해싱 등).

또한 해시 함수 자체를 값이 고르게 분산되도록 설계하고, 배열 크기를
데이터 양에 맞춰 늘리는 **리사이징(Resizing)**을 통해 충돌 확률을
낮게 유지한다.
