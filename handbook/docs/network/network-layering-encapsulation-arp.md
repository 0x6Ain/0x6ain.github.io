# 네트워크 계층 구조와 캡슐화, IP/MAC 주소, ARP

## 계층화된 네트워크 설계 (OSI 7계층)

네트워크 통신은 컴퓨터 간에 데이터를 주고받는 작업 전체를 하나의 덩어리로 처리하지 않고, 역할에 따라 **7개의 계층(Layer)**으로 나눠서 설계한다.

| 계층 | 이름 | 예시 |
|---|---|---|
| 7 | 응용 (Application) | 웹브라우저, 이메일 앱 |
| 4 | 전송 (Transport) | TCP, UDP |
| 3 | 네트워크 (Network) | IP, 라우팅 |
| 2 | 데이터링크 (Data Link) | MAC 주소, 이더넷 |
| 1 | 물리 (Physical) | 케이블, 전기/광 신호 |

각 계층은 자신의 바로 위/아래 계층하고만 정해진 방식(인터페이스)으로 소통하고, 다른 계층이 내부적으로 어떻게 동작하는지는 전혀 알 필요가 없다.

### 왜 계층으로 나눴을까

계층을 나눈다고 처리해야 할 데이터 양이 줄어드는 것은 아니다. 오히려 계층마다 헤더가 붙기 때문에 데이터 크기는 커진다. 계층화의 진짜 목적은 **관심사의 분리(Separation of Concerns)**와 **캡슐화(encapsulation)**다.

예를 들어 이메일 앱은 "이 데이터를 상대방에게 보내달라"고 요청만 하면 되고, 그 데이터가 와이파이로 가는지 광케이블로 가는지는 전혀 몰라도 된다. 반대로 물리 계층의 전송 기술(전화선 → 케이블 → 광섬유 → 5G)이 아무리 바뀌어도, 그 위의 IP, TCP, 그리고 응용 프로그램은 코드를 고칠 필요가 없다.

만약 계층 구조 없이 하나로 뭉쳐서 설계했다면, 물리적 연결 방식 하나가 바뀔 때마다 신호 처리 코드부터 라우팅 코드, 연결 관리 코드, 앱 로직까지 뒤섞여 있어 어디를 고쳐야 할지 애매하고 다른 부분까지 건드려 버그가 생길 위험이 커진다. 계층화된 설계에서는 해당 계층의 코드만 교체하면 되므로 유지보수성과 확장성이 크게 높아진다.

## 캡슐화와 역캡슐화

계층을 나눴어도 결국 데이터는 하나로 합쳐져 전선을 타고 흐른다. 받는 쪽이 "이 부분은 몇 계층 정보인지"를 구분할 수 있는 이유는, 각 계층이 데이터를 아래로 넘길 때마다 자신만의 **헤더(header)**를 덧붙이기 때문이다. 이 과정을 **캡슐화(encapsulation)**라고 한다.

```
7계층(응용): 이메일 내용 그 자체
                ↓
4계층(전송): [TCP 헤더 | 이메일 내용]                     ← 세그먼트
                ↓
3계층(네트워크): [IP 헤더 | TCP 헤더 | 이메일 내용]        ← 패킷
                ↓
2계층(데이터링크): [이더넷 헤더 | IP 헤더 | TCP 헤더 | 이메일 내용]  ← 프레임
                ↓
1계층(물리): 전기/광 신호로 변환하여 전송
```

헤더 안에는 "다음엔 어떤 프로토콜로 넘겨야 하는지" 알려주는 필드가 들어있다.

- 이더넷 헤더의 `Type` 필드: 안에 든 것이 IPv4임을 표시 (`0x0800`)
- IP 헤더의 `Protocol` 필드: 안에 든 것이 TCP임을 표시 (`6`)
- TCP 헤더의 `Port` 필드: 어떤 응용 프로토콜인지 표시 (80번 = HTTP, 443번 = HTTPS)

참고로 용어상 2계층 단위는 **프레임**, 3계층 단위는 **패킷**, 4계층 단위는 **세그먼트(TCP)/데이터그램(UDP)**라고 구분해서 부른다.

받는 쪽은 반대로 1계층부터 7계층 방향으로 올라가면서 헤더를 하나씩 벗기는데, 이를 **역캡슐화(decapsulation)**라고 한다. 각 헤더의 필드를 읽어 "다음엔 IP로 → 다음엔 TCP로 → 다음엔 앱으로" 순서대로 위 계층에 넘겨주며, 이 과정을 **디멀티플렉싱(demultiplexing)**이라고도 한다.

### 헤더를 붙이는 순서와 벗기는 순서는 정반대다

캡슐화와 역캡슐화는 **LIFO(Last In, First Out)** 구조를 갖는다. 즉 가장 나중에 붙은 헤더가 가장 먼저 벗겨진다. 택배를 포장할 때 내용물 → 비닐 → 박스 → 운송장 순서로 겹겹이 싸고, 뜯을 때는 운송장 → 박스 → 비닐 → 내용물 순서로 벗기는 것과 같은 원리다.

```
[보낼 때]                          [받을 때]
7→4: TCP 헤더 붙임                 1→2: 물리 신호 → 프레임 복원
4→3: IP 헤더 붙임                  2→3: 이더넷 헤더 벗김 (Type 필드 확인)
3→2: 이더넷 헤더 붙임               3→4: IP 헤더 벗김 (Protocol 필드 확인)
2→1: 전기/광 신호로 변환            4→7: TCP 헤더 벗김 (Port 번호 확인)
```

가장 마지막에 붙인 이더넷 헤더가 받는 쪽에서는 가장 먼저 벗겨진다.

## IP 주소 vs MAC 주소

IP 주소만으로 통신이 될 것 같지만, 실제로는 IP 주소와 MAC 주소가 각각 다른 역할을 담당하며 함께 쓰인다.

### 역할의 차이

| 구분 | IP 주소 | MAC 주소 |
|---|---|---|
| 성격 | 논리적 주소 (Logical Address) | 물리적 주소 (Physical Address) |
| 구조 | 계층적(hierarchical) — 국가/도시/동네처럼 구조화 | 평면적(flat) — 하드웨어에 새겨진 고유 번호 |
| 역할 | 출발지에서 목적지까지 전체 경로 안내 (라우팅) | 한 구간(hop) 안에서 실제 배달 담당 |
| 변경 여부 | 네트워크를 옮기면 바뀔 수 있음 | 랜카드 고유값, 기기를 옮겨도 안 바뀜 |

비유하자면 IP 주소는 택배 상자에 적힌 "서울시 강남구 ○○동" 같은 최종 배송지 주소이고, MAC 주소는 그 동네에서 실제로 문을 두드리는 집배원이 확인하는 문패에 해당한다.

### 경로를 거치는 동안 무엇이 바뀌는가

여러 라우터를 거쳐 목적지까지 갈 때, **IP 주소는 끝까지 그대로 유지**되지만 **MAC 주소는 매 구간(hop)마다 새로 바뀐다.** (NAT라는 예외가 있지만 별도 주제)

```
PC(내 컴퓨터) --- Router1 --- Router2 --- Server(목적지)
```

| 구간 | 출발지 MAC | 목적지 MAC | 출발지 IP | 목적지 IP |
|---|---|---|---|---|
| PC → Router1 | PC의 MAC | Router1의 MAC | 항상 동일 | 항상 동일 |
| Router1 → Router2 | Router1의 MAC | Router2의 MAC | 항상 동일 | 항상 동일 |
| Router2 → Server | Router2의 MAC | Server의 MAC | 항상 동일 | 항상 동일 |

IP 주소는 "최종 목적지"를 가리키는 값이라 편지 봉투의 수신 주소처럼 끝까지 바뀌면 안 되고, MAC 주소는 "바로 다음 구간에서 누구에게 넘길지"만 나타내는 값이라 릴레이 경주에서 바통을 넘길 때마다 다음 주자가 바뀌듯 매 구간 갱신되어야 한다. 라우터가 하는 핵심 동작 중 하나가 바로 패킷을 받으면 **IP 헤더는 그대로 두고 이더넷(MAC) 헤더만 새로 만들어 다음 구간으로 전달하는 것**이다.

## ARP (Address Resolution Protocol)

라우터(혹은 일반 PC)가 다음 구간 장비의 MAC 주소를 알아내려면 **ARP 테이블(ARP Cache)**이라는 "IP 주소 ↔ MAC 주소" 매핑 정보를 참조한다. 이 매핑을 처음 알아내는 절차가 ARP(Address Resolution Protocol)다.

동작 순서:

1. 장비가 특정 IP(X)의 MAC 주소를 모르는 상태가 되면
2. 같은 네트워크 전체에 **ARP Request**를 브로드캐스트로 뿌린다. ("IP가 X인 장비, 네 MAC 주소를 알려줘")
3. IP가 X인 장비만 반응하여 **ARP Reply**로 자신의 MAC 주소를 응답한다.
4. 요청한 장비는 이 응답을 **ARP 테이블에 저장**해두고, 이후에는 다시 묻지 않고 캐시에서 꺼내 쓴다. (일정 시간이 지나면 캐시가 만료되어 다시 조회해야 한다)

새 아파트 단지에 이사 와서 특정 호수에 사는 사람을 모를 때, 관리사무소 방송으로 "○○님 계시면 나와주세요"라고 전체 방송(브로드캐스트)하고, 응답한 사람의 얼굴(MAC)을 그 이후로 기억해두는 것과 같은 방식이다.
