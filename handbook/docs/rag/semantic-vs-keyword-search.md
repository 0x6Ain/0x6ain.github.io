# 의미 검색 vs 키워드 검색

## 키워드(전문) 검색

단어의 **겹침과 빈도**로 매칭한다. 대표적으로 BM25, TF-IDF 랭킹이 있고,
Postgres 전문검색(`tsvector`/`tsquery`)이나 Elasticsearch가 이 방식이다.

- 장점: 정확한 용어·고유명사·에러코드에 강하고, 빠르고 저렴하며 외부
  모델 의존이 없다.
- 단점: 단어가 겹치지 않으면 못 찾는다. 동의어·유의어·의도 파악이
  약하다.

## 의미 검색 (임베딩)

임베딩 벡터의 유사도로 **뜻**을 매칭한다.

- 장점: 단어가 달라도 의미로 찾는다("운동 모임" ↔ "자전거 클럽").
- 단점: 임베딩 모델이 필요하고, 정확한 고유명사·숫자·코드 매칭엔 오히려
  약할 수 있다.

## 한국어에서의 키워드 검색 주의점

한국어는 영어처럼 공백으로 단어가 깔끔히 나뉘지 않는다. 그래서 키워드
검색을 제대로 하려면 **형태소 분석기**(mecab-ko/은전한닢,
Elasticsearch Nori)나 **n-gram**(`pg_bigm`, `pg_trgm`)이 필요하다. 이
처리가 없으면 조사·어미 때문에 매칭이 잘 안 된다.

## 하이브리드 검색 (실무 정답)

정확한 용어는 키워드가, 뉘앙스·의도는 임베딩이 강하므로 둘을 합쳐
랭킹하는 하이브리드가 실무의 기본이다. 두 랭킹을 합치는 대표적 방법이
**RRF(Reciprocal Rank Fusion)** 다.

```
# 각 검색 결과의 "순위"만으로 점수를 매겨 합산 (k는 상수, 보통 60)
score(doc) = Σ  1 / (k + rank_i(doc))
             i ∈ {키워드 검색, 임베딩 검색}
```

RRF는 두 검색의 점수 스케일이 달라도(코사인 유사도 vs BM25 점수)
**순위 기반**으로 공정하게 합칠 수 있어 자주 쓰인다.

## 의미 검색이 항상 더 나은가요?

아니다. 제품명·에러코드·주문번호처럼 **정확한 문자열**을 찾을 때는
키워드 검색이 더 정확하다. 반대로 "혼자 가도 어색하지 않은 모임" 같은
자연어·의도 질의는 임베딩이 낫다. 그래서 대부분 하이브리드로 간다.

## 임베딩 없이 검색만 하려면?

키워드(전문) 검색만으로도 가능하고, 이 경우 신경망 모델이 전혀 필요
없다. 다만 "뜻으로 찾는" 능력은 포기해야 한다. 검색어가 주로 정확한
용어라면 키워드만으로 충분하고, 자연어 질의가 많다면 임베딩(또는
하이브리드)이 필요하다.
