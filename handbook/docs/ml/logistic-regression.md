# 로지스틱 회귀와 경사하강법

## 개념

로지스틱 회귀는 **입력 피처들의 가중합을 시그모이드 함수에 통과시켜
0~1 사이의 확률**을 예측하는 가장 기본적인 지도학습 모델이다. "이
유저가 이 아이템을 클릭할 확률" 같은 이진 분류(클릭/안 클릭,
좋아요/패스) 문제에 흔히 쓰인다.

```
z = w1*x1 + w2*x2 + ... + wn*xn + b   (선형 결합)
pred = 1 / (1 + e^-z)                  (시그모이드로 0~1 확률로 변환)
```

`z`는 -∞~+∞ 아무 값이나 될 수 있어서 그 자체로는 "확률"로 쓸 수 없다.
시그모이드가 이 값을 항상 0~1 사이로 눌러준다(z=0이면 0.5, z가 크게
양수면 1에 가까워지고 음수면 0에 가까워짐).

## 학습 — 경사하강법(Gradient Descent)

목표는 예측(`pred`)이 실제 라벨(`y`, 0 또는 1)과 최대한 가깝게 만드는
가중치 `w`, `b`를 찾는 것.

1. **예측 오차 계산**: `err = pred - y`
   - 실제 클릭했는데(`y=1`) `pred`가 낮았으면 `err`가 음수(많이 틀림)
   - 실제 안 눌렀는데(`y=0`) `pred`가 높았으면 `err`가 양수(많이 틀림)
2. **가중치를 오차 방향으로 조금씩 이동**:
   ```
   w[i] -= lr * (err * x[i])
   b    -= lr * err
   ```
   "이 피처가 클수록, 그리고 예측이 틀린 정도가 클수록, 그 가중치를
   더 많이 고친다"는 뜻. `lr`(learning rate)이 이동 보폭을 정한다.
3. 이 과정을 전체 데이터에 대해 평균 내어 한 번 갱신하고(1 epoch),
   수백~수천 번 반복하면 가중치가 실제 패턴에 서서히 수렴한다.

### 왜 수천 번(epoch)이나 반복하나?

`lr`이 작을수록 한 스텝의 이동량이 작기 때문이다. `lr`을 크게 하면
빨리 수렴하지만 최적점을 지나쳐 진동·발산할 위험이 있고, 작게 하면
안전한 대신 여러 번 반복해야 한다. 실무에서는 **손실(loss)이 더 이상
줄지 않으면 조기 종료**하는 방식(scikit-learn의 `lbfgs`가 기본으로
해줌)을 쓰지, 고정된 epoch 수만 믿고 도는 건 초반 10~20%에서 이미
수렴이 끝나는 경우가 많아 비효율적일 수 있다.

### 손실 함수 (Binary Cross-Entropy)

```
loss = -(y * log(pred) + (1-y) * log(1-pred))
```

`y=1`인데 `pred`가 0에 가까우면(완전히 틀림) `log(pred)`가 -∞에
가까워져 loss가 폭발적으로 커진다 — "확신을 가지고 틀리면 크게
벌준다"는 뜻. 초기(가중치가 전부 0)의 이론적 loss는 `ln(2) ≈ 0.693`
(무조건 50%로 찍었을 때의 값)이며, 학습이 진행되며 이 값이 줄어드는
것으로 수렴 여부를 확인한다.

## 과적합(Overfitting)과 L2 정규화

**과적합**은 모델이 학습 데이터의 진짜 패턴이 아니라, 그 데이터에만
있는 우연한 노이즈까지 외워버려서 새로운 데이터에서는 성능이
떨어지는 현상이다. 피처가 많거나 데이터가 적을수록 심해진다.

**L2 정규화**는 가중치 갱신에 페널티 항을 하나 끼워 넣어서 막는다:

```
w[i] -= lr * (err * x[i] + l2 * w[i])
//                          ^^^^^^^^^ 가중치가 클수록 더 세게 끌어당김
```

가중치가 커질수록 매 스텝마다 더 세게 작아지는 방향으로 끌려가므로,
"데이터를 완벽히 맞추는 것"보다 "적당히 단순한(가중치가 작은) 모델"을
선호하게 된다. 노이즈를 외우려면 가중치가 커져야 하는데 그걸 억제하는
원리다. 데이터가 피처 수 대비 충분히 많으면(예: 피처 4개에 샘플
1만 건 이상) 정규화 없이도 큰 문제는 없는 경우가 많다.

## 실무 파이프라인 — 학습과 서빙의 분리

```
[배치 학습 스크립트] → [학습된 가중치 파일] → [서빙 서버가 로드]
```

- **배치 학습**: 쌓인 로그(impression → click/apply 등)로 경사하강법을
  돌려 가중치를 찾는다. 한 번(또는 주기적으로) 실행하면 끝 — 서빙
  트래픽마다 다시 돌 필요 없음.
- **가중치 파일**: 학습 결과(숫자 몇 개)만 저장한 산출물. 서빙
  서버는 이 파일을 시작 시 한 번 읽어서 메모리에 올려두고 재사용한다.
- **점수 계산(서빙)**: 매 요청마다 `w1*x1 + w2*x2 + ... + b` 가중합만
  계산하면 되므로 매우 가볍다.

이 분리 덕분에 무거운 학습 연산과 가벼운 서빙 연산이 완전히 분리되고,
가중치를 다시 학습해도 서빙 서버 코드는 바뀌지 않는다(파일만
교체). **피처 엔지니어링 시 반드시 지켜야 할 것**: 학습 데이터를
만들 때 각 샘플의 피처는 "그 시점 이전"의 이력만 사용해야 한다(예:
impression 시점보다 이후에 일어난 클릭을 피처에 포함시키면 미래
데이터가 새는 leakage가 발생해 실제 서빙 시점엔 재현 불가능한 성능이
나온다).

## 자주 나오는 질문

**Q. 왜 선형 회귀가 아니라 로지스틱 회귀를 쓰나요?**
선형 회귀는 출력이 -∞~+∞라 확률로 해석할 수 없다. 시그모이드를 씌워
0~1로 제한하면 "확률"이라는 의미를 가지며, 손실 함수도 확률에
적합한 형태(cross-entropy)를 쓸 수 있다.

**Q. 로지스틱 회귀의 한계는?**
피처들의 **단순 선형 결합**만 표현 가능하다. "A는 크고 B는 작을 때만
특별히 중요하다" 같은 피처 간 비선형 상호작용은 못 잡는다. 이런
한계를 넘으려면 [신경망](neural-networks.md)처럼 층을 쌓거나, 트리
기반 모델(XGBoost, LightGBM)로 넘어간다.

**Q. scikit-learn 대신 직접 구현해본 이유는?**
의존성을 최소화해야 하는 환경(예: 별도 Python 런타임을 못 들이는
Node.js 프로젝트)에서는 로지스틱 회귀를 손으로 구현하거나 Node
생태계의 경량 ML 라이브러리(`ml-logistic-regression` 등)를 쓴다.
알고리즘 자체(순전파 → 오차 계산 → 경사하강법 갱신)는 동일하며,
라이브러리는 이 반복 연산을 행렬곱으로 벡터화해 더 빠르게 처리해줄
뿐이다.
