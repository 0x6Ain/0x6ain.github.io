# Memory 구조

## 프로세스 메모리 영역

프로세스는 실행되면 아래 네 영역으로 메모리를 구성한다.

- **Code(Text)** — 실행할 명령어(컴파일된 코드)가 저장된다. 읽기
  전용이다.
- **Data** — 전역 변수, static 변수처럼 프로그램 실행 내내 유지되는
  값이 저장된다.
- **Heap** — 런타임에 동적으로 할당되는 메모리. 개발자(또는 런타임)가
  명시적으로 할당/해제한다.
- **Stack** — 함수 호출 시 생성되는 지역 변수, 매개변수, 반환 주소가
  저장된다. 함수가 반환되면 자동으로 정리된다.

## Heap vs Stack

| | Stack | Heap |
|---|---|---|
| 할당/해제 | 함수 호출/반환 시 자동 | 명시적 할당, GC 또는 수동 해제 |
| 속도 | 빠름 (포인터 이동 수준) | 상대적으로 느림 |
| 크기 | 제한적 (초과 시 Stack Overflow) | 상대적으로 큼 |
| 생명주기 | 함수 실행 동안만 | 명시적으로 해제하거나 GC가 회수할 때까지 |
| 접근 범위 | 해당 함수(스코프) 내부 | 여러 함수/스레드에서 참조 가능 |

## Virtual Memory (가상 메모리)

프로세스에게 실제 물리 메모리 용량과 무관하게 독립적이고 연속된
주소 공간을 제공하는 기법.

- 프로세스마다 자신만의 가상 주소 공간을 가지므로, 서로 다른
  프로세스의 메모리를 직접 침범할 수 없다 (메모리 보호).
- 실제 물리 메모리보다 큰 프로그램도 실행할 수 있다 (필요한 부분만
  물리 메모리에 적재).
- MMU(Memory Management Unit)가 가상 주소를 물리 주소로 변환한다.

## Paging

가상 메모리를 일정 크기의 **페이지(Page)** 단위로 나누고, 물리
메모리도 같은 크기의 **프레임(Frame)** 단위로 나누어 매핑하는 방식.

- 페이지 테이블이 가상 페이지 → 물리 프레임 매핑 정보를 관리한다.
- 필요한 페이지만 물리 메모리에 적재하고, 당장 쓰지 않는 페이지는
  디스크(스왑)로 내보낼 수 있다 (Demand Paging).
- 외부 단편화(연속된 빈 공간 부족 문제)를 방지할 수 있다.
