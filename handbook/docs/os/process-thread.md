# 프로세스, 스레드, Context Switching

## 프로세스와 스레드 차이

- **프로세스**: 실행 중인 프로그램의 인스턴스. 독립된 메모리 공간
  (Code, Data, Heap, Stack)을 가진다. 프로세스 간에는 메모리를
  공유하지 않는다.
- **스레드**: 프로세스 내부에서 실행되는 흐름의 단위. 같은 프로세스에
  속한 스레드끼리는 Code/Data/Heap 영역을 공유하고, Stack만 각자
  독립적으로 가진다.

메모리를 공유하기 때문에 스레드 간 통신은 빠르지만, 동시에 같은
데이터에 접근할 때 [Race Condition](../database/race-condition.md)이
발생할 수 있어 동기화가 필요하다.

## Context Switching

CPU가 하나의 프로세스/스레드 실행을 멈추고 다른 프로세스/스레드를
실행하도록 전환하는 것.

**비용이 발생하는 이유**

- 현재 실행 상태(레지스터, 프로그램 카운터 등)를 저장하고, 다음에
  실행할 대상의 상태를 복원해야 한다.
- 프로세스 간 전환은 메모리 주소 공간(페이지 테이블, TLB 등)까지
  교체해야 하므로 스레드 간 전환보다 비용이 크다.
- 캐시(CPU Cache)에 적재돼 있던 데이터가 무효화되어, 전환 직후
  캐시 미스가 늘어난다.

이런 이유로 Context Switching이 잦으면 실제 연산에 쓰이는 시간이
줄어들어 전체 처리량이 떨어진다.

## Node.js는 싱글 스레드인데 어떻게 동시에 많은 요청을 처리하나요?

Node.js의 자바스크립트 실행 자체는 싱글 스레드지만, **Event Loop**와
**비동기 I/O**를 이용해 동시성을 확보한다.

- 네트워크 요청, 파일 I/O, DB 쿼리 같은 I/O 작업은 커널이나 별도의
  워커 스레드 풀(libuv의 Thread Pool)에 위임하고, JS 스레드는 그
  결과를 기다리지 않고 다음 작업을 계속 처리한다.
- I/O 작업이 끝나면 완료된 콜백이 Event Loop의 큐에 쌓이고, JS
  스레드는 이 큐를 순서대로 꺼내 실행한다.
- 따라서 CPU 연산이 아니라 I/O 대기가 대부분인 웹 서버 워크로드에서는
  스레드를 여러 개 두지 않고도 많은 요청을 동시에 처리할 수 있다.

단, CPU 바운드 작업(무거운 연산)은 싱글 스레드를 그대로 점유해 다른
요청 처리를 막으므로, Worker Threads나 별도 프로세스로 분리해야 한다.
