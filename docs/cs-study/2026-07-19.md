# OS

## 핵심 개념 요약

**1. 프로세스(Process)**
- 프로그램은 디스크에 저장된 정적 실행 파일, 프로세스는 그 프로그램이 메모리에 올라가 실행 중인 상태
- 각 프로세스는 독립된 **주소 공간(Address Space)**을 가지며, 다른 프로세스의 메모리에 직접 접근 불가
- 이유: **오류 격리(Fault Isolation)** — 한 프로세스의 버그나 악성 동작이 다른 프로세스로 전파되는 것을 방지 (안정성 + 보안)
- OS는 **가상 메모리(Virtual Memory)** 기법으로 각 프로세스가 마치 메모리를 독점하는 것처럼 착각하게 만듦

**2. IPC (Inter-Process Communication)**
격리된 프로세스끼리 안전하게 통신하기 위해 OS가 제공하는 공식 통로들:
- **파이프(Pipe)**: 한 프로세스의 출력을 다른 프로세스의 입력으로 연결 (예: `ls | grep`)
- **공유 메모리(Shared Memory)**: 특정 메모리 영역을 두 프로세스가 공유하도록 허용 (가장 빠르지만 동기화 문제는 프로그래머가 처리)
- **소켓(Socket)**: 네트워크 통신처럼 메시지 주고받기 (같은 컴퓨터 내에서도, 다른 컴퓨터와도 가능)
- **시그널(Signal)**: 간단한 이벤트 알림 (예: `Ctrl+C` → SIGINT)
- **메시지 큐(Message Queue)**: 메시지를 큐에 넣고 빼는 비동기 통신
- 핵심: 프로세스가 직접 통신하는 게 아니라, **커널이 중재자** 역할을 하며 이때 사용하는 것이 **시스템 콜(System Call)**

**3. 커널 모드 vs 유저 모드**
- CPU가 하드웨어적으로 권한을 두 단계로 분리
- **유저 모드**: 일반 프로세스가 실행되는 모드, 특권 명령어(하드웨어 직접 제어 등) 실행 불가
- **커널 모드**: OS만 접근 가능, 하드웨어 자유롭게 제어 가능
- 프로세스가 하드웨어 자원이 필요하면 **시스템 콜**을 호출 → CPU가 유저 모드에서 커널 모드로 전환 → 커널이 검증 후 처리
- 이렇게 막아놓은 이유: ① 보호(버그 프로그램이 시스템 훼손 방지) ② 자원 중재(여러 프로세스 간 충돌 방지) ③ 보안(악성 프로그램의 시스템 장악 방지)

**4. 시스템 콜의 오버헤드**
- 시스템 콜 호출 시 내부적으로: (1) 유저→커널 모드 전환 및 레지스터 값 저장 (2) 커널의 요청 검증 (3) 작업 수행 후 커널→유저 모드 복귀 및 레지스터 복원
- 이 과정이 일반 함수 호출보다 수십~수백 배 느릴 수 있음
- 시스템 콜을 아주 자주(예: 파일을 한 글자씩 읽기) 호출하면, 실제 작업 비용보다 모드 전환 오버헤드가 누적되어 더 커지는 비효율 발생

## Q&A 하이라이트

- **Q: 왜 OS는 각 프로세스마다 독립된 주소 공간을 줄까?**
  A(사용자): 하나라도 오류가 나면 전체가 망가지니까 → 코치가 **오류 격리(Fault Isolation)** 개념으로 확인/보강

- **Q: 격리된 프로세스끼리 통신이 필요할 때 OS는 어떻게 처리할까?**
  A: 사용자가 답을 모른다고 하여 코치가 **IPC(파이프, 공유 메모리, 소켓, 시그널, 메시지 큐)** 및 **시스템 콜을 통한 커널 중재** 개념을 설명

- **Q: 프로세스는 왜 커널 도움 없이 직접 하드웨어나 다른 프로세스에 접근하지 못할까?**
  A: 사용자가 모른다고 하여 코치가 **커널 모드 vs 유저 모드** 개념 설명 (보호, 자원 중재, 보안 목적)

- **Q: 시스템 콜을 아주 자주 호출하면 성능은 어떻게 될까?**
  A(사용자): 성능이 느려질 것 같다 → 정답, 코치가 **모드 전환 비용(레지스터 저장/복원, 검증 과정)** 으로 구체적 설명 보강

- **(진행 중 질문, 미답변)**: 한 글자씩 매번 시스템 콜을 부르는 대신 호출 횟수를 줄이는 방법은? (힌트: "한 번에 몰아서 처리" → 버퍼링/배치 처리 개념으로 이어질 것으로 보이나 대화에서 답은 나오지 않음)

## 헷갈렸던 부분 / 더 공부할 것

- 사용자는 IPC의 구체적 처리 방식, 커널/유저 모드 전환 메커니즘, 시스템 콜 비용의 원리에 대해 스스로 답하지 못하고 코치의 설명에 의존함 → 개념 자체를 처음 접하는 부분으로 보임
- 마지막에 제시된 **"시스템 콜 호출 횟수를 줄이는 방법(버퍼링/배치 처리로 추정)"** 질문은 대화가 끝나는 시점까지 답변되지 않음 → 다음 학습에서 이어서 확인 필요 (예: 버퍼링(Buffering), 표준 입출력 라이브러리의 버퍼 사용 등과 연결될 가능성)
